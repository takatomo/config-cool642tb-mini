## キーの重複入力対策

左右とも、押下・解放のデバウンス時間を10msに設定しています。
対象はそれぞれの側の全キーです。スイッチの接点が短時間揺れても、複数回の入力として扱われにくくします。

## Bluetooth切り替え後の英数入力

`&bt_english n` はBluetooth接続先 `n` を選択し、次の条件が揃ってから `LANG2` の押下・解放を1回送信します。
接続先0〜4を選ぶ既存の `bt_sel_*` マクロすべてが対象です。

- 選択した接続先に接続されている。
- Bluetooth接続が暗号化され、相手がキーボード入力通知を受け取れる状態になっている。
- 実際のキーボード出力先が、そのBluetooth接続先になっている。
- Ctrl・Shift・Alt・Commandなどの修飾キーが解放されている。

接続待ちの途中で別の接続先を選んだ場合は、古い要求を取り消します。押下済みの英数キーは同じ接続先へ解放を送り、USB接続先へは送信しません。
暗号化の確立に失敗した場合は、同じ接続先を選び直すと再試行します。
通常のレイヤー切り替えでは英数キーを送りません。

英数切り替えには既存のJ＋K同時押しと同じ `LANG2` を使います。macOSの日本語入力では英数キーとして扱われます。[ZMKのキーコード一覧](https://zmk.dev/docs/keymaps/list-of-keycodes#language)
ほかのOSでも、そのキーが英数切り替えに割り当てられている必要があります。

専用処理はこのリポジトリのZephyr moduleとして右側に組み込まれます。
通常キーと英数キーの通知が混ざってキー状態を壊さないように、`bt_gatt_notify_cb` のうちキーボード入力通知を直列化しています。マウス・consumer通知はそのまま通します。
`.keymap` だけを別のリポジトリへコピーする場合は、`src/`、`dts/`、`CMakeLists.txt`、`zephyr/module.yml` も必要です。

## 検証と反映

ホスト上の動作テストは次のコマンドで実行します。

```sh
sh tests/bt_english/run.sh
```

ファームウェアは `build.yaml` の左右の構成でビルドし、デバウンスを両側へ反映するために左右とも書き込みます。
ZMK Studioで接続先キーを変更している場合は、既存の `bt_sel_*` マクロを割り当ててください。
`bt_english` をStudioから直接追加するためのパラメーター編集には対応していません。

実機では、Enterの短押しで重複入力や入力抜けがないこと、接続済み端末への切り替えと未接続端末の再接続後に英数になること、接続待ち中に別の接続先へ変更しても古い要求が送られないことを確認します。
ホスト上のテストやビルドの成功は、実際のBluetooth通信やOS側の入力方式が切り替わったことの確認とは別です。
